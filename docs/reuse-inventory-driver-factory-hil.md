## Reused integration
- Added a device-spec JSON Schema that captures exact identity/protocol claims, one functional class, transport(s), four behavioral axes, OS execution targets, and a safety-role reference.
- Added the six-class taxonomy and an explicitly software-only example profile.
- Linked this schema and taxonomy to the existing device dossier workflow; current driver families and platform maturity statements remain unchanged.

The JSON Schema is formally validated with the existing WSL `jsonschema` installation. The existing Python harness tests structural invariants with only the Python standard library so it remains dependency-free on Windows. These additions are requirements/profile artifacts. They do not generate or implement drivers, make a QEMU device model, verify a physical device, or make a safety claim.
